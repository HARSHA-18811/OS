1. Executive Summary & Architecture Overview

This project presents a dual-tier Operating Systems engineering architecture developed for the 3rd Semester Operating Systems course. The project bridges the fundamental gap between low-level bare-metal hardware abstraction and full-scale modern Linux distribution engineering:

  • Tier 1 — Debian MicroOS: An ultra-lightweight (<450 MB) bootable Live Linux hybrid ISO based on Debian 12 Bookworm. It boots in under 15 seconds directly into an automated graphical desktop environment customized to mirror Windows 11 ergonomics (bottom taskbar, Whisker Start menu, system monitor, file manager, and browser). It features non-root passwordless autologin, an integrated retro arcade Snake game, and an academic Producer-Consumer Concurrency Research Laboratory.
  • Tier 2 — RustOS: A 32-bit x86 bare-metal operating system kernel written in 100% freestanding Rust (#![no_std], #![no_main]). It implements low-level protected mode hardware initialization, Global Descriptor Table (GDT), 256-entry Interrupt Descriptor Table (IDT), 8259 Dual PIC remap, PIT timer scheduling, direct memory-mapped VGA text buffer driver (0xb8000), PS/2 keyboard controller, and an interactive kernel shell with arcade mini-games.

2. Steps on How the Operating System Was Implemented

2.1 Implementing the Bare-Metal Kernel (RustOS)

RustOS executes directly on x86 hardware without any existing operating system or C runtime library. The implementation follows standard systems programming methodologies:

  1. Freestanding Compilation & Linker Script: The kernel is compiled targeting i686-unknown-none via custom specification i686-rustos.json with red-zone and SSE disabled. The linker script (linker.ld) aligns sections on 4 KB page boundaries and embeds a Multiboot header at 1 MB (0x100000), transferring control to the kernel entry point _start.
  2. Global Descriptor Table (GDT): Implemented in rustos/src/gdt.rs, establishing flat protected-mode segments for Kernel Code (index 1, execute/read) and Kernel Data (index 2, read/write) with base 0x00000000 and limit 0xFFFFFFFF.
  3. Interrupt Descriptor Table (IDT) & CPU Exceptions: In rustos/src/idt.rs, a 256-entry gate array is registered using the lidt instruction. It captures hardware faults including Division Error (0), Invalid Opcode (6), Double Fault (8), General Protection Fault (13), and Page Fault (14), extracting the CR2 faulting address and formatting register state dumps.
  4. Dual 8259 PIC Remap & PIT Timer: In rustos/src/pic.rs, hardware IRQs are remapped from the default vectors 0x08-0x0F (which collide with Intel CPU exceptions) to 0x20-0x2F. In rustos/src/pit.rs, Channel 0 of the 8253/8254 timer chip is set to square-wave generator mode, producing millisecond-accurate scheduling ticks for kernel multitasking.
  5. VGA Text Driver & Synchronization: In rustos/src/vga.rs, characters are written directly into physical video memory at 0xb8000 (80 columns × 25 rows). Each cell stores an ASCII character and a 1-byte color attribute. Protected by a spinlock mutex with automatic scrolling and formatted print!/println! macros.
  6. PS/2 Keyboard Driver & Interactive Shell: In rustos/src/keyboard.rs, IRQ1 decodes Scan Code Set 1 from I/O port 0x60 into ASCII keystrokes. In rustos/src/shell.rs, an interactive prompt evaluates commands: help, info, ticks, clear, and bare-metal games (Snake, Car Dodge).

2.2 Implementing Debian MicroOS (Live Graphical Desktop System)

  1. Base System Bootstrap: Minimal Debian 12 Bookworm bootstrap using debootstrap --variant=minbase, selecting linux-image-amd64, live-boot, and systemd-sysv.
  2. Windows-Style GUI Architecture: Built with Xorg, LightDM, and XFCE4. The taskbar is anchored to the bottom screen edge (position=p=12) featuring the Whisker Application Menu (Start Menu), pinned taskbar buttons (Terminal, File Manager, Browser, Task Manager), and system tray clock.
  3. Automated Non-Root Autologin: LightDM configured in /etc/lightdm/lightdm.conf with autologin-user=user and user-session=xfce. User user is pre-seeded with passwordless sudo permissions.
  4. Retro Arcade Snake Game Integration: Integrated nsnake with system symlinks /usr/bin/snake and a dedicated desktop launcher /home/user/Desktop/snake.desktop launching xfce4-terminal -e "/usr/games/nsnake".

3. Steps on How the ISO File Was Created from Source Code

Forming a production-grade, bootable hybrid ISO requires strict filesystem hierarchy preservation, static device node management, and bootloader integration.

3.1 Debian MicroOS Headless Build Pipeline (build_clean.sh)

  1. Clean & Safe Mount Management: Unmounts existing virtual filesystems (dev/pts, dev, proc, sys, run) lazily to prevent host lockups, then initializes clean staging directories (chroot/, iso/live/, iso/isolinux/).
  2. System Bootstrap: Runs debootstrap --variant=minbase --arch=amd64 bookworm chroot.
  3. Chroot Customization: Mounts host virtual filesystems into chroot, installs the Linux 6.1 kernel, XFCE4 desktop, LightDM, snake game, creates user accounts, and builds desktop shortcuts.
  4. Kernel & Initramfs Staging: Extracts vmlinuz and initrd.img from chroot/boot/ to iso/live/.
  5. Static Device Node Injection (Crucial): Before unmounting, static device nodes are created: 
    mknod -m 600 chroot/dev/console c 5 1
mknod -m 666 chroot/dev/null c 1 3
  6. Filesystem Cleanup & Mount Point Retention: Unmounts chroot filesystems, then verifies that placeholder mount directories (/proc, /sys, /dev, /run, /tmp) exist with correct permissions.
  7. SquashFS Compression: Compresses the rootfs using high-efficiency XZ compression, excluding only the boot directory: 
    mksquashfs chroot iso/live/filesystem.squashfs -comp xz -e boot
  8. ISOLINUX & Hybrid MBR Authoring: Authors isolinux.cfg and uses xorriso with -isohybrid-mbr to produce a dual-mode hybrid ISO bootable on both optical media and USB flash drives: 
    xorriso -as mkisofs -r -V "MicroOS" -J -l -b isolinux/isolinux.bin -c isolinux/boot.cat \
  -no-emul-boot -boot-load-size 4 -boot-info-table \
  -isohybrid-mbr /usr/lib/ISOLINUX/isohdpfx.bin \
  -o build/micro-os.iso iso
CRITICAL FIX #1 (Mount Directory Preservation): Running mksquashfs with -e boot proc sys run tmp completely stripped the physical mount point directories. At boot, live-boot failed with mount: /root/run: mount point does not exist. Solution: Only exclude boot (-e boot) and ensure clean placeholder directories exist.
CRITICAL FIX #2 (Kernel Panic on Init): Missing /dev/console and /dev/null caused systemd to abort before devtmpfs was mounted, triggering Kernel panic: Attempted to kill init! exitcode=0x00000100. Solution: Pre-create static device nodes with mknod prior to compression.

3.2 RustOS Bare-Metal ISO Creation Pipeline

  1. The kernel binary is compiled: cargo build --target i686-rustos.json.
  2. The binary is placed in an ISO root structure: iso/boot/kernel.elf.
  3. A GRUB 2 configuration is written to iso/boot/grub/grub.cfg: 
    set timeout=3
set default=0
menuentry "RustOS" {
    multiboot /boot/kernel.elf
    boot
}
  4. grub-mkrescue -o rustos/iso/rustos.iso rustos/iso bundles GRUB stages and the Multiboot ELF kernel into a bootable 15 MB ISO.

4. Concurrency Research Paper Analysis & Experimental Lab (pclab)

4.1 Research Overview & Mathematical Model

The research lab investigates synchronization overhead, thread contention, and buffer capacity trade-offs in the classic Producer-Consumer Multi-Core Synchronization Model.

Under Little's Law for queueing networks:
$$\mathbf{L = \lambda_{eff} \cdot W}$$
Where $L$ is the average items in the buffer, $\lambda_{eff}$ is effective departure rate, and $W$ is the mean waiting time per item in the buffer.

The lab compares standard mutual exclusion with condition variables (std::sync::Mutex, std::sync::Condvar) against lock-free queues across 24 experimental configurations.

4.3 Academic Hypotheses & Conclusions

  • Hypothesis 1 (Buffer Size Sweet Spot): Increasing buffer capacity from $B = 1$ to $B = 64$ delivers an exponential 274% to 450% throughput improvement. Beyond $B = 64$, diminishing returns occur (only 1.9% gain between 64 and 512). The sweet spot represents matching cache line granularity.
  • Hypothesis 2 (Asymmetric Workloads): In skewed thread setups ($4P \times 1C$ or $1P \times 4C$), throughput is strictly capped at ~888k ops/sec because the lone thread is 100% CPU saturated regardless of buffer expansion.
  • Hypothesis 3 (Lock Contention Ceiling): Increasing threads to $8P \times 8C$ results in a 14% performance degradation compared to $4P \times 4C$ (dropping from 2.38M to 2.05M ops/sec). Under high thread counts, mutex cache-line invalidations (MESI protocol bouncing) dominate CPU cycles.

5. Deployment, Virtualization & Faculty Defense Guide

5.1 1-Click Windows Launcher (Start-MicroOS.bat)

An automated batch script at the repository root auto-detects VirtualBox, registers the VM with 2048 MB RAM, 2 vCPUs, and 128 MB VRAM, attaches micro-os.iso, and launches the VM into full-screen mode with one double-click.

5.2 Display Resolution & Fullscreen

Instant Full-Screen Display: Press Right Ctrl + C to toggle Scale Mode, stretching the desktop to 100% of your monitor without black borders. Press Right Ctrl + F to enter borderless full-screen mode.
